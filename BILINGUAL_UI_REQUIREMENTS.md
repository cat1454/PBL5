# Bilingual UI Requirements

This repo uses a bilingual UI standard for all user-facing frontend work.

## Mandatory Rule

- Any new frontend feature, screen, component, modal, form, button, label, tooltip, toast, empty state, loading state, error message, or helper text must be implemented in both languages:
- English (`en`)
- Vietnamese with proper diacritics (`vi`)

## Applies To

- New UI features
- Updates to existing UI copy
- New status messages and validation messages
- New navigation items, page titles, and settings labels
- New workspace, quiz, flashcard, slide, upload, and analysis flows

## Implementation Expectations

- Do not ship new hardcoded UI text in only one language.
- When adding or changing frontend copy, update the shared translation dictionary for both `vi` and `en` in the same task.
- Vietnamese text must use proper accents and correct UTF-8 display.
- If a feature introduces new user-facing states, all states must have both language variants.
- If backend data is dynamic content generated by the system or user, only translate the static UI shell unless the product explicitly requires content translation.

## Definition Of Done

- The feature works in both `vi` and `en`.
- Language toggle changes the new UI immediately without missing labels.
- No new UI string is left untranslated in either language.
- Any new validation, success, loading, and error messages exist in both languages.

## Agent Instruction

- Treat bilingual support as a default requirement, not an optional polish task.
- If a frontend feature cannot reasonably be completed in both languages, call that out explicitly before considering the task done.
